# 과제 12: 퀵 정렬의 피벗 선택에 따른 성능 비교

## 1. 실험 개요

동일한 무작위 정수 데이터(0\~99999, 중복 허용)에 대해 세 가지 피벗 선택
방법으로 퀵 정렬을 수행하고, 정렬 과정에서 발생한 **숫자 비교 횟수**를
측정하였다.

- 데이터 크기: n = 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000
- 각 크기에서 세 방법은 **같은 원본 데이터의 복사본**을 사용하였다.
- 피벗 선택 방법
  1.  **First**: 구간의 첫 번째 원소
  2.  **Random**: 구간에서 무작위 위치의 원소(분할할 때마다 새로 선택)
  3.  **Median-3**: 첫 번째, 가운데, 마지막 원소 중 중앙값
- 세 방법은 피벗을 고르는 함수만 다르고, 분할(`partition`) 알고리즘은
  동일하다.
- 비교 횟수에 포함한 것:
  - 분할 중 `arr[j] <= pivot` 비교
  - Median-3에서 중앙값을 정하기 위한 비교
- 포함하지 않은 것:
  - 반복문 조건 검사
  - 무작위 위치 생성
  - 데이터 이동(`swap`)
- 정렬 후 `isSorted()`로 오름차순 정렬 여부를 검사했으며, 모든 경우
  정상적으로 정렬되었다.

### 2.1 First 대비 증감률

First를 기준으로 Random과 Median-3의 비교 횟수가 얼마나 증가하거나
감소했는지 계산하였다.

           n      Random    Median-3

---

       1,000       -3.1%       -0.8%
       2,000      -12.7%      -15.4%
       4,000       +9.1%       -2.7%
       8,000       +3.7%       -6.0%
      16,000       +4.3%       +1.8%
      20,000       +4.8%       -1.7%

- `+`는 First보다 비교 횟수가 많다는 뜻이다.
- `-`는 First보다 비교 횟수가 적다는 뜻이다.
- 평균은 각 데이터 크기에서 계산한 증감률의 산술평균이다.

## 3. 분석

### 3.1 데이터 크기 증가에 따른 비교 횟수 변화

세 방법 모두 데이터 크기 n이 커질수록 비교 횟수가 대체로 `n log n`에
가까운 형태로 증가하였다. n이 1,000에서 20,000으로 20배 커졌을 때 비교
횟수는 First 약 30.9배, Random 약 33.4배, Median-3 약 30.6배 증가하였다.
이는 `n log₂ n`의 증가 비율인 약 28.7배와 비슷한 규모이며, `n²`의 증가
비율인 400배와는 큰 차이가 있다.

따라서 이번 무작위 데이터 실험에서는 세 방법 모두 평균적인 퀵 정렬의
성능 특성인 `O(n log n)`에 가까운 증가 경향을 보였다고 해석할 수 있다.
다만 데이터 크기별 측정값은 한 번의 실행 결과이므로 이 결과만으로 모든
입력에서의 성능을 단정할 수는 없다.

### 3.2 피벗 선택 방법별 성능 차이

- **Median-3**는 6개 크기 중 4곳(2,000 / 4,000 / 8,000 / 20,000)에서
  가장 적은 비교 횟수를 기록했다. First 대비 평균 약 4.1% 적었다. 다만
  n = 16,000에서는 First보다 약 1.8% 많았다.
- **Random**은 n = 1,000에서 가장 적은 비교 횟수를 기록했지만, 6개 중
  4곳에서 가장 많은 비교 횟수를 기록했다. First 대비 평균 약 1.0%
  많았다.
- **First**는 n = 16,000에서 가장 적은 비교 횟수를 기록했다.

이번 실험에서는 Median-3가 전반적으로 가장 좋은 결과를 보였지만, 모든
데이터 크기에서 항상 가장 적은 비교 횟수를 기록한 것은 아니다. n =
1,000에서는 Random이, n = 16,000에서는 First가 더 적은 비교 횟수를
기록했다.

각 데이터 크기에서 한 번만 측정했기 때문에 작은 차이는 무작위 데이터의
구성에 따른 영향일 수 있다. 따라서 특정 피벗 방법이 모든 상황에서 항상
빠르다고 단정하기보다는, 여러 데이터 크기에서 나타난 전체적인 경향을
중심으로 해석해야 한다.

### 3.3 피벗 선택이 분할 결과와 비교 횟수에 영향을 주는 이유

퀵 정렬은 분할 한 번에 현재 구간의 원소들을 피벗과 비교하고, 이후 두
부분 배열을 재귀적으로 정렬한다. 따라서 전체 비교 횟수는 **재귀 깊이**와
**각 분할이 얼마나 균등한가**에 영향을 받는다.

- 피벗이 중앙값에 가까우면 배열이 거의 절반씩 나뉘어 재귀 깊이가 약
  `log n`이 되고, 전체 비교 횟수가 줄어드는 경향이 있다.
- 피벗이 최솟값이나 최댓값에 가까우면 한쪽 부분 배열이 거의 비어
  분할이 치우친다. 이 경우 재귀 깊이가 커지고 비교 횟수도 증가할 수
  있다.

**First**는 구간의 첫 번째 원소를 피벗으로 선택하므로 값의 크기를
고려하지 않는다. 무작위 데이터에서는 첫 원소도 무작위 값이므로
평균적으로 괜찮은 분할을 만들 수 있다. 그러나 이미 정렬된 데이터나 역순
데이터에서는 피벗이 계속 구간의 최솟값 또는 최댓값이 될 수 있어 분할이
매우 불균형해지고, 최악의 경우 `O(n²)`으로 성능이 악화될 수 있다.

**Random**은 매 분할마다 피벗 위치를 무작위로 선택한다. 입력이 특정한
순서로 정렬되어 있더라도 항상 첫 원소를 선택하는 방식의 취약점을 줄일 수
있다. 다만 무작위 선택이므로 운이 나쁘면 극단적인 값이 피벗으로 선택되어
분할이 치우칠 수도 있다. 이번 실험처럼 원본 데이터 자체가 무작위인
경우에는 First 역시 사실상 무작위 위치의 값을 선택하는 효과가 있으므로
두 방법의 차이가 항상 크게 나타나는 것은 아니다.

**Median-of-Three**는 첫 번째, 가운데, 마지막 원소 중 중앙값을 피벗으로
선택한다. 세 값 중 가장 작은 값이나 가장 큰 값을 피하는 데 도움이 되므로
극단적인 피벗을 선택할 가능성을 줄이고, 보다 균형 잡힌 분할을 기대할 수
있다. 대신 중앙값을 고르는 과정에서 추가 비교가 발생한다. 따라서 분할
균형 개선으로 줄어드는 비교 횟수와 피벗 선택에 추가되는 비교 횟수를 함께
고려해야 한다. 이번 실험에서도 Median-3가 대부분의 데이터 크기에서 좋은
결과를 보였지만, n = 16,000에서는 First보다 비교 횟수가 많았다.

### 3.4 어떤 방법이 효과적이었는가

이번 무작위 데이터 실험에서는 **Median-of-Three가 전반적으로 가장
효과적**이었다. 6개 데이터 크기 중 4곳에서 가장 적은 비교 횟수를
기록했고, First 대비 평균 약 4.1% 적었다. 또한 모든 데이터 크기에서
Random보다 비교 횟수가 적었다.

다만 Median-3가 모든 크기에서 항상 가장 좋은 것은 아니었다. n =
1,000에서는 Random이, n = 16,000에서는 First가 가장 적은 비교 횟수를
기록했다. 이는 무작위 데이터의 구성과 피벗 선택 결과에 따라 실제 비교
횟수가 달라질 수 있기 때문이다.

종합하면 이번 실험에서는 Median-of-Three가 가장 좋은 경향을 보였지만,
무작위 데이터에서 First와의 차이가 아주 크지는 않았다. 또한 정렬된
데이터나 역순 데이터에 대한 추가 실험을 수행하지 않았으므로, 이번 결과는
무작위 데이터에 한정해서 해석해야 한다.

### 3.5 실험의 한계

- 각 데이터 크기에서 한 번만 측정했으므로 작은 차이는 통계적으로
  확실하지 않을 수 있다. 여러 번 반복하여 평균을 구하면 더 신뢰할 수
  있는 결과를 얻을 수 있다.
- 무작위 데이터만 사용하였다. 정렬된 데이터, 역순 데이터, 중복이 많은
  데이터에서는 결과가 달라질 수 있다.
- 실행할 때마다 난수가 달라지므로 비교 횟수도 달라질 수 있다.

## 4. \[보너스\] 재귀적 퀵 정렬과 반복적 퀵 정렬 비교

### 4.1 구현과 측정 방법

- 반복적 퀵 정렬(`quickSortIterative`)은 배열로 만든 **명시적 스택**에
  `(low, high)` 쌍을 `push/pop`하며 정렬한다.
- 재귀적 방법과 **같은 피벗 선택 방법(Median-of-Three)** 및 **같은
  `partition` 함수**를 사용한다.
- 데이터 크기는 n = 10,000이며, 같은 원본 데이터를 사용하였다.
- 한 번의 측정 시간은 짧기 때문에 200회 반복한 평균 실행 시간을
  사용하였다.
- 시간은 정렬 함수 호출 전후에만 `clock_gettime`으로 측정하였다.
  데이터 생성, 배열 복사(`memcpy`), 출력은 측정 시간에서 제외하였다.
- 두 방법의 비교 횟수가 같은지, 정렬 결과가 올바른지도 프로그램 안에서
  확인하였다.
- 컴파일은 별도의 최적화 옵션 없이 다음 명령으로 수행하였다.

```bash
gcc -Wall -Wextra main.c data.c quicksort.c bonus.c -o quicksort
```

### 4.2 결과

실행 결과는 다음과 같다.

```text
Data Size : 10000
Pivot     : Median-of-Three
Number of runs: 200

Recursive Quick Sort : 0.8550 ms
Iterative Quick Sort : 0.9221 ms
```

방법 평균 실행 시간

---

Recursive Quick Sort 0.8550 ms
Iterative Quick Sort 0.9221 ms

반복적 방법은 재귀적 방법보다 약 0.0671 ms, 비율로는 약 7.8% 더 느리게
측정되었다.

### 4.3 분석

두 방법은 같은 피벗 선택 방법과 같은 `partition` 함수를 사용하므로 분할
과정에서 수행하는 데이터 비교 횟수는 같았다. 실제 프로그램에서도 두
방법의 비교 횟수가 같고, 두 결과 모두 정상적으로 정렬되었음을
확인하였다.

실행 시간 차이는 재귀 호출과 스택 관리 방식의 차이에서 발생할 수 있다.
재귀적 방법은 함수 호출을 통해 실행 구간을 관리한다. 반면 반복적 방법은
명시적 스택 배열에 구간의 시작과 끝 인덱스를 저장하고, `push/pop`
과정에서 `top` 인덱스를 갱신하고 배열에 접근한다. 이러한 추가 작업이
반복적 방법의 실행 시간에 영향을 주었을 가능성이 있다.

따라서 이번 측정에서는 반복적 방법이 함수 호출을 사용하지 않는다는
이유만으로 더 빠르지는 않았다. 다만 실행 시간 차이는 크지 않으며, 컴퓨터
환경, 컴파일 옵션, 시스템 부하에 따라 결과가 달라질 수 있다.

반복적 방법의 장점은 재귀 호출을 직접 스택으로 관리할 수 있다는 점이다.
재귀적 방법은 분할이 매우 불균형한 경우 재귀 깊이가 커질 수 있다. 반복적
방법은 스택 사용 방식을 직접 제어할 수 있지만, 스택 크기와 사용량을
고려하여 구현해야 한다.

## 5. 실행 방법

소스 파일 네 개(`main.c`, `data.c`, `quicksort.c`, `bonus.c`)를 같은
폴더에 둔다. 터미널에서 해당 폴더로 이동한 다음 아래 명령을 실행한다.

```bash
gcc -Wall -Wextra main.c data.c quicksort.c bonus.c -o quicksort
./quicksort
```

컴파일할 때 `main.c`만 지정하면 다른 파일에 구현된 함수들을 찾지 못해
링크 오류가 발생할 수 있다. 따라서 네 개의 `.c` 파일을 모두 컴파일
명령에 포함해야 한다.

## 6. 결론

이번 과제에서는 First, Random, Median-of-Three의 세 가지 피벗 선택
방법을 동일한 무작위 데이터에 적용하여 비교 횟수를 측정하였다. 실험 결과
Median-of-Three가 6개 데이터 크기 중 4곳에서 가장 적은 비교 횟수를
기록했고, First 대비 평균 비교 횟수도 약 4.1% 적었다.

보너스 실험에서는 같은 피벗 선택 방법과 분할 함수를 사용하는 재귀적 퀵
정렬과 반복적 퀵 정렬을 비교하였다. 두 방법의 비교 횟수는 같았으며, 이번
실행 환경에서는 재귀적 방법의 평균 실행 시간이 더 짧게 측정되었다.

이번 실험을 통해 퀵 정렬의 성능은 피벗 선택에 따른 분할 균형에 영향을
받으며, 반복적 구현이 항상 재귀적 구현보다 빠른 것은 아니라는 점을
확인하였다.
